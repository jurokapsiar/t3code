## Integration mechanism and coverage

apps/server/src/factory/Factory.integration.test.ts starts two controlled source HTTP/WebSocket services on ephemeral loopback ports with separate scoped temporary homes, plus a scoped temporary factory home and SQLite database. The test uses the production FactoryRuntime.layer() and real NodeSource ticket, WebSocket, and RPC clients. It exercises discovery, OAuth token exchange, session validation, ticket issuance, and the real /ws JSON-RPC connection. Stream queues and source synchronization frames mark progress; there are no sleeps, polling loops, or timeout-success assertions.

Coverage includes equal project/thread IDs across environments, empty projects, contract-decoded snapshots, deltas, contiguous metadata revisions, scope denial, standard source scopes, credential redaction from metadata/SQLite/WAL, source disconnect/retry/reset freshness, metadata surviving factory restart while remote summaries start empty, and factory-disabled passive startup. The exact full-overview key uniqueness invariant is asserted after initial load and reconnect. The existing factory HTTP tests cover bootstrap origin/pairing URL behavior and keep reserved API/upgrade routes out of the SPA fallback; client transport tests cover relative same-origin discovery. These were not a single browser-to-Vite-to-factory session.

The UI additions cover all 10,000 sessions in selectors, application of a complete snapshot whose encoded JSON is exactly 8 MiB, explicit blocking on overview-too-large rather than showing partial state, and the exact 150 KiB growth boundary. Factory enrollment credentials remain transient to the enrollment flow; UI sensitive-operation and migration tests ran in the Phase 1 suite.

## Handoff manifest

**Artifact:** @t3tools/contracts 0.0.48, t3tools-contracts-0.0.48.tgz, SHA256 d49bf602c0178a1e67b9022cc655effb87194014fca7d576297a54bee1d7ab8b. The consumer pins exactly one Effect peer, 4.0.0-rc.115.

**Protocols and scopes:** Factory protocol 1; the UI checks the server's factory capability and protocol before opening overview streams. Source orchestration protocol 2; the controlled sources provide server config and active shell streams with batched replay and completion markers. The source token exchange requests only AuthStandardClientScopes: orchestration:read, orchestration:operate, terminal:operate, review:write, and relay:read. Factory read RPCs require factory:read; metadata control RPCs require factory:control; environment enrollment/update/remove/retry require factory:admin. The test confirms a read-only principal is denied control access. Access-write and relay-write scopes are not granted. The UI wire limits are 10,000 threads and 8 MiB encoded snapshot size.

**Routes / boundary:** Browser requests stay on the page origin: GET /factory/bootstrap, GET /api/auth/session, GET /.well-known/t3/environment, and WS /ws?orchestrationProtocol=2. Vite's explicit proxy map is /ws (WebSocket), /api, /factory/bootstrap, /factory/env (WebSocket upgrade), /oauth, and /.well-known. /factory/env is reserved for the source relay and is not implemented by this phase; it is not a broad /factory proxy. The factory server reaches a configured source only through the discovery, token-exchange, session-validation, ticket, and /ws paths: GET /.well-known/t3/environment, POST /oauth/token, GET /api/auth/session, POST /api/auth/websocket-ticket, and WS /ws with a ticket and orchestration protocol query. These are server-to-source requests; the browser has no source-origin fallback. Source endpoint origins are user-configured http(s) URLs without embedded credentials; there is no hostname allowlist. Renewal was not exercised because the fixture advertises it as unsupported.
