T3 Code setup guide

Install, start, pair, and verify the T3 Code web app from this repository.

Before you start

Use Node.js 24.13.1 or newer in the Node 24 line. The repository currently warns on Node 24.12.0. Keep provider CLIs and credentials configured separately.

Install and run

  1. Open a terminal in the repository

    cd /home/juro/projects/t3code

  2. Install workspace dependencies

    ./node_modules/.bin/vp i

    From a clean checkout, install the package manager dependencies first if node_modules does not exist.

  3. Start the isolated development app

    ./node_modules/.bin/vp run dev

    The development runner uses this worktree's ignored .t3 state by default. Do not point it at the shared live T3 home.

  4. Pair the browser

    Copy the complete startup URL printed by the runner. It ends in /pair#token=.... Open it once in the browser that you will use for T3 Code.

  5. Add or select a project

    Choose Add project, select a workspace directory on the T3 server machine, and wait for the project to appear in the left rail.

  6. Start a thread

    Create a new thread, confirm the project name in the composer header, select a provider and model, then send a short prompt such as Print the current working directory.

Current OpenCode status

The repository is not yet fully functional for the reported OpenCode flow. The investigation is recorded in project_fix.md, but the underlying fixes have not been implemented.

Known symptoms are: the first response may not appear, OpenCode may use the T3 server's startup directory instead of the selected project, and a failed first-turn bootstrap may leave no thread in the rail.

Use another provider for a reliable smoke test until the proposed cwd and startup-reconciliation fixes land.

Smoke test checklist

  1. Confirm the app loads after pairing.
  2. Confirm the selected project name matches the intended folder.
  3. Send a prompt with a known-good provider.
  4. Confirm both user and assistant messages appear.
  5. Confirm the new thread remains in the left rail.
  6. Stop the dev process with the PID you started when testing is complete.
